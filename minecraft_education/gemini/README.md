# マイクラ設計図メーカー — Gemini版の使い方

Gemini に「◯◯の設計図を作って」とお願いすると、レゴの説明書のような設計図ができます。
**インストール・アカウント登録・お金は一切かかりません。**
学校やクラブのパソコン、タブレット、家のパソコン、どれでも同じように使えます。

必要なファイルはこの2つだけです。

| ファイル | なにに使う |
|---|---|
| **PROMPT.md** | Gemini に貼り付ける「おまじない」の文章 |
| **viewer.html** | 設計図を表示する画面。パソコンに保存して使う |
| **AGENT_PROMPT.md** | （おまけ）エージェントに自動で建てさせたい人用。下の方法3を見る |

---

## はじめの準備（1回だけ）

1. **viewer.html** をパソコンに保存する（右クリック →「名前を付けて保存」）
   - デスクトップなど、すぐ見つかる場所がおすすめです
   - みんなで使うときは、共有フォルダやUSBに入れて配ってください
2. 保存した **viewer.html をダブルクリック**して開けるか確認する
   - 「設計データを貼り付けてください」と出れば成功です

> **インターネットがつながっていなくても開けます。** 学校のパソコンでも大丈夫です。

---

## 方法1: いつもの作り方（おすすめ）

### 1. Gemini に「おまじない」を貼る

[Gemini](https://gemini.google.com/) を開いて、**PROMPT.md** の
`【ここから】` から `【ここまで】` までをコピーして貼り付け、送信します。

> 貼り付けるのは、**その会話の1回目だけ**でOKです。
> 同じ会話の中なら、2つめ3つめの設計図は「次は◯◯を作って」だけで作れます。

### 2. 作りたいものを伝える

```
お城の設計図を作って
```

こんなふうに、ひとことでOKです。くわしく言うほど、思いどおりになります。

```
15×15マスくらいの、堀と跳ね橋がある小さなお城の設計図を作って
```

### 3. 出てきた JSON をコピーする

Gemini が `{` で始まる文章（JSON といいます）を出します。
コードのブロックの右上にあるコピーボタンを押してください。

### 4. viewer.html に貼る

保存しておいた **viewer.html** を開いて、まん中の大きな枠に貼り付け、
**「設計図を作る」**ボタンを押します。設計図ができます。

### 5. 印刷する

右下の **「印刷する」**ボタンを押すと、紙に印刷できます。
画面を見ながら作るより、印刷して手元に置いたほうが作りやすいです。

## レッドストーンの仕掛けを作ったとき

設計にレッドストーン（ダスト・トーチ・ピストン・感圧板・レバー等）が入っていると、
設計図に **「レッドストーン回路のくわしい図」** が自動で追加されます。頼まなくても付きます。

1. **回路だけの立体図** — 建物から回路だけを切り出して立体で表示。色のついたものが
   レッドストーン部品、薄いものは支えのブロックとピストンが押す先。
   床や壁は描かないので、配線のつながりが立体で一目で分かります
2. **部品と役割** — 部品ごとに、座標と「回路で何をしているか」の説明
   （トーチは何をするか、ピストンはどちらへ何を押すか）
3. **段ごとの位置** — 上から見た大きな図。まわり2マスの支えのブロックも薄い色で表示。
   ピストンなど向きが要る部品には**向きの矢印**が出ます

回路は1マスずれただけで動かなくなります。全体の設計図は「建物を作る」ための図なので、
仕掛けはこちらの図で位置を確かめながら作ってください。

---

## 画面のいちばん上に出る「自動検品」を必ず見る

設計図の上に、こんな帯が出ます。

| 表示 | 意味 | どうする |
|---|---|---|
| **✅ 自動検品: 合格** | よくある失敗が見つからなかった | そのまま作ってOK |
| **⚠ ◯件の問題** | あぶない所が見つかった | 下のとおり Gemini に直してもらう |

⚠ が出たら、**書いてある内容をそのままコピーして** Gemini にこう言ってください。

```
自動検品でこう言われました。直したJSONをもう一度出して。

（ここに⚠の内容を貼る）
```

> **なぜこの機能があるか**
> いちばん多い失敗は「説明文に書いてある座標と、図の座標がずれている」ことです。
> 見た目ではまず気づけませんが、そのとおりに作ると仕掛けが動きません。
> この検品は、人が見落とすそういう間違いを機械が見つけてくれます。

## 方法2: Gemini の画面だけで完結させる（Canvas を使う）

viewer.html を開くのも面倒、という場合はこちらです。

1. Gemini で **Canvas** をオンにする（入力欄の下にあるボタン）
2. **viewer.html をテキストエディタで開いて全部コピーし**、Canvas に貼り付ける
3. 「この HTML の `var DESIGN = null;` の部分を、お城の設計データに書き換えて」と頼む
4. Canvas の**プレビュー**に設計図が出ます

同じ会話の中なら、次からは「次は灯台に変えて」と言うだけで作り直せます。

> Canvas は Gemini の標準機能です（[公式の説明](https://gemini.google/overview/canvas/)）。
> 見あたらないときは方法1を使ってください。結果は同じです。

---

## 方法3: エージェントに自動で建てさせる（AGENT_PROMPT.md）

設計図を見ながら手で建てるかわりに、**エージェント（ロボット）に建てさせる**こともできます。

1. **AGENT_PROMPT.md** の `【ここから】`〜`【ここまで】` を Gemini に貼る
2. 「お城を作って」のように頼むと、**MakeCode Python のコード**が出てくる
3. Minecraft Education で **Cキー** → Code Builder → **MakeCode（Python）** を開き、
   コードを貼り付けて実行する
4. 建てたい場所に立って、チャットで `build` と打つ（**建て終わるまで動かない！**）

ドア・階段・レッドストーンの仕掛けも、**向きごと自動で置かれます**
（向きの指定は Mojang 公式データと照合済みのコマンドを使います）。

> - Gemini が書き換えるのは設計データ（文字の地図と置き物リスト）だけで、
>   エージェントを動かすプログラム部分は毎回同じ固定コードです
> - MakeCode のブロック定数名は実機の Code Builder で検証済みです。
>   ランタンと石レンガのハーフブロックだけは MakeCode に存在しないため、
>   近い見た目のブロックで代用されます
> - 仕掛けがうまく置かれないときは、世界の設定で「チートの実行」がオンか
>   確認してください（置き物はコマンドで置くため）

## うまくいかないとき

| こまったこと | なおしかた |
|---|---|
| 「JSON が見つかりません」と出る | `{` から `}` までを貼れているか確認。説明文が混ざっていても大丈夫です |
| 「JSON の形が正しくありません」と出る | Gemini に「JSONだけをもう一度出して」と頼む。途中で切れていることが多いです |
| 設計図が真っ白になる | viewer.html をもう一度開き直してから貼り直す |
| ⚠ が何度も消えない | 作りたいものを小さくする（32×32マス以内）と成功しやすいです |
| 大きすぎると言われる | 上限は 64×64マス・48段・20000ブロックです。「大きめ」の参考表示なら、そのまま作って大丈夫 |
| Gemini が図を描こうとする | 「図はいらない。JSONだけ出して」と伝える |

---

## みんなで使うときのコツ

- **viewer.html を共有フォルダに1つ置いておく**と、全員が同じものを使えます
- 印刷するときは、ブラウザの印刷設定で「**背景のグラフィック**」をオンにすると、
  ブロックの色がついたまま印刷できます
- タブレットでも見られます。横向きにすると段の図が見やすいです
- できた設計図のページは、そのまま保存して友だちに渡せます（1ファイルで完結しています）

## 中身を直したい人へ（大人向け）

`renderer.js` が**唯一の正本**です。ここを直したら、必ず次を実行してください。

```bash
cd minecraft_education/gemini
python3 sync_palette.py   # palette.py のブロックを renderer.js へ転記
python3 build_pack.py     # PROMPT.md と viewer.html を作り直す
python3 compare.py        # Python版と図が一致するか検証（回路詳細図も含む）
node test_validate.js     # 検品ロジックの検証
python3 test_pack.py      # 回帰テスト
```

`PROMPT.md`・`viewer.html`・`AGENT_PROMPT.md` は**自動生成物なので直接編集しないでください**。
直接編集すると renderer.js とズレて、設計図の品質が静かに下がります。
ブロックを増やすときは **`blueprint/palette.py` だけ**に足し、`sync_palette.py` を実行してください。
`renderer.js` のパレットとプロンプトのブロック表は、そこから自動で作られます。
